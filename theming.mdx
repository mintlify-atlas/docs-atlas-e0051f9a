baseui-cn uses CSS custom properties for every design token — colors, radius, and surface values — following the same variable naming convention as shadcn/ui. If you are already running a shadcn/ui theme, every token name you know transfers directly. If you are starting fresh, `npx baseui-cn init` injects a complete set of default variables into your global stylesheet automatically.

## How the token system works

Variables are defined as **oklch color values**, which provide a perceptually uniform color space and accurate opacity modifiers. The `init` command writes an `@theme inline` block in your global CSS file that maps the custom properties to Tailwind color tokens:

```css
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-secondary: var(--secondary);
  --color-secondary-foreground: var(--secondary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-accent: var(--accent);
  --color-accent-foreground: var(--accent-foreground);
  --color-destructive: var(--destructive);
  --color-destructive-foreground: var(--destructive-foreground);
  --color-success: var(--success);
  --color-success-foreground: var(--success-foreground);
  --color-warning: var(--warning);
  --color-warning-foreground: var(--warning-foreground);
  --color-info: var(--info);
  --color-info-foreground: var(--info-foreground);
  --color-border: var(--border);
  --color-input: var(--input);
  --color-ring: var(--ring);
  --color-card: var(--card);
  --color-card-foreground: var(--card-foreground);
  --color-popover: var(--popover);
  --color-popover-foreground: var(--popover-foreground);
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
  --radius-xl: calc(var(--radius) + 4px);
}
```

With this mapping in place, Tailwind utility classes like `bg-primary`, `text-muted-foreground`, and `border-border` resolve to your custom property values out of the box. No additional Tailwind configuration is required.

## Dark mode

Dark mode is implemented with a `.dark` class on the `html` or `body` element. Toggle it in JavaScript to switch themes at runtime:

```ts
document.documentElement.classList.toggle("dark")
```

All components read their colors from CSS variables, so toggling the class is the only change required — no component-level updates needed.

<Tip>
  Prefer using `prefers-color-scheme` to follow the system preference automatically. Add a `@media (prefers-color-scheme: dark)` block that applies the same `.dark` variable overrides.
</Tip>

## Migrating from shadcn/ui

Because baseui-cn uses identical CSS variable names to shadcn/ui, migrating your theme requires minimal renaming. The main difference is that baseui-cn uses **oklch** color values rather than HSL channel values, and adds semantic tokens for `--success`, `--warning`, and `--info` states. You can either convert your existing HSL values to oklch, or keep your HSL values as-is — browsers support both formats.

<Note>
  The component source files themselves are different — baseui-cn components use `@base-ui/react` primitives rather than Radix UI. Only the CSS variable tokens are compatible. You will need to replace component files rather than copying them from a shadcn/ui project.
</Note>
